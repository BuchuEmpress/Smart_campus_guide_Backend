Backend Integration Checklist

1) Base URL
- Production: set by deployment (Render `startCommand` uses $PORT). Example production base: https://api.smart-campus.example.com
- Staging: e.g., https://staging-api.smart-campus.example.com
- Path prefix: /api (all routes are mounted under /api, e.g., /api/topics/search)

2) Health endpoint
- Path: /health
- Example success response (HTTP 200):
  {"status":"healthy","timestamp":"2025-12-19T...","environment":{...},"services":{...}}

3) Auth scheme
- Current: none (no JWT/OAuth implemented). Routes use no authentication.
- Recommendation: add JWT (Bearer) with endpoints:
  - /auth/login → returns { "access_token": "<jwt>", "token_type": "bearer", "expires_in": 3600 }
  - /auth/refresh → returns refreshed token
  - Token format: JWT (RS256 recommended), access expiry e.g. 1h, refresh expiry e.g. 30d
  - If using OIDC: expose /.well-known/openid-configuration and JWKS URL

4) CORS policy
- Current allowed origins (configured in api/main.py):
  - https://smart-campus-guide-frontend.vercel.app
  - http://localhost:3000
  - http://localhost:5173
  - http://127.0.0.1:3000
  - http://127.0.0.1:5173
- Allowed methods: *
- Allowed headers: *
- Credentials: allowed (allow_credentials=True)

5) TLS / SSL
- Typical setup: TLS terminated at Load Balancer / CDN (Render provides TLS for service domains).
- HTTPS should be mandatory for clients in production.

6) Rate limits & retry guidance
- Rate limiter present via slowapi.Limiter.
- Examples:
  - Root `/` limited to 100/min
  - `/health` limited to 200/min
- Recommendation for frontend:
  - On 429: respect Retry-After header if present; otherwise exponential backoff starting 1s → 2s → 4s (max ~16s) and max 3 retries.
  - Return code: 429 for throttling.

7) API versioning and compatibility
- Current: app version="1.0.0" and routes mounted at /api.
- Recommendation: use path versioning for breaking changes, e.g. /api/v1/... and bump to /api/v2 for breaking releases.
- Deprecation policy: advertise breaking changes 30–90 days before removal.

8) Error response format
- Global exception handler returns JSON similar to:
  { "error": "Internal server error", "detail": "...", "path": "/api/...", "timestamp": "..." }
- Recommendation (standardized):
  { "error": { "message": "Human message", "code": "ERR_CODE", "details": {...} } }

9) Important endpoints used by the frontend
- Auth (if added): POST /auth/login, POST /auth/refresh
- Health: GET /health
- Cache:
  - GET /cache/download (see api/routes/cache.py for exact path)
- Topics:
  - POST /api/topics/search — body: { "query":"...", "limit":5, "department":..., "option":..., "year":..., "status":... }
    - Example success: returns TopicSearchResponse with topics array
  - GET /api/topics — list topics (query params: department, option, year)
  - GET /api/topics/{topic_id} — single topic
  - POST /api/topics/sync — trigger Qdrant sync (returns 202)
  - GET /api/topics/sync/status — pollable sync status
- Navigation: check api/routes/navigation.py for route names (e.g., /api/navigation/...)
- Diagnostics: GET /api/topics/qdrant-health (temporary diagnostic endpoint)

10) Cookie/session settings (if using cookies)
- Current: no server-side session cookies used for auth. Chat sessions use session_id supplied in request body.
- If cookies added: set HttpOnly, Secure, SameSite=Lax (or Strict if single-site), domain = frontend domain.

11) Deployment & DNS details
- Hosting platform: Render (see render.yaml).
- Env var names (used in code / render.yaml):
  - GOOGLE_MAPS_API_KEY, GEMINI_API_KEY, MONGODB_URI, QDRANT_HOST, QDRANT_API_KEY, DEBUG_MODE, API_HOST, API_PORT
- Frontend env var to configure: VITE_API_URL (or similar) → https://api.example.com
- Start command: uvicorn api.main:app --host 0.0.0.0 --port $PORT
- Path rewrites: API base is /api — ensure gateway/proxy preserves prefix.

12) DB migrations & rollback procedure
- Current: migration helper scripts/migrate_to_mongodb.py to import JSON into MongoDB.
- No formal migration tool configured (e.g., mongock/alembic).
- Recommendation:
  - Use a migration tool (e.g., mongock, mongo-migrate) for schema changes.
  - Rollback: manual rollback script or snapshot-based rollback (restore from backup). Always backup DB before migration.

13) Monitoring & health hooks
- Health endpoint: /health
- App exposes request timing header X-Process-Time on responses.
- Recommend: add metrics (Prometheus), structured logs (JSON), and a post-deploy webhook that calls /health and GET /api/topics/sync/status / sample search to verify behavior.

14) Temporary test credentials
- No staging user exists by default.
- Recommendation: create a staging user record in MongoDB or issue a long-lived JWT for smoke tests (scoped read-only).
- Example test token env var: TEST_API_TOKEN="eyJhbGci..."

15) Additional notes
- Required env vars for runtime: GEMINI_API_KEY, MONGODB_URI, QDRANT_HOST, QDRANT_API_KEY, GOOGLE_MAPS_API_KEY
- Custom headers currently used: X-Process-Time (response header).
- Client IP restrictions: rate-limiter uses remote address; if behind proxies, set trusted hosts / X-Forwarded-For handling.
- Fallbacks: /api/topics/search implements semantic search → text fallback → MongoDB fallback and a soft-filter ranking system (so frontend can rely on results even with partial indexing).
