SMART CAMPUS GUIDE: ULTIMATE API BLUEPRINT FOR AI FRONTEND GENERATION

================================================================================ GLOBAL CONFIGURATION & SETUP
Base URL: http://localhost:8000/api
Frontend Stack Recommendation: React + Tailwind CSS + Lucide Icons.
State Management: Use a global store (e.g., Zustand or Redux) to persist session_id and user_location.
Primary Colors: Royal Blue (#003366) and Campus Green (#2E7D32).
================================================================================ NAVIGATION & LOCATIONS SERVICE
SMART SEARCH (POST /navigation/search)
Used for the global search bar. It understands natural language.

Request: { "query": "Where is the Faculty of Engineering?" }

Response: { "locations": [ { "id": "eng_building_01", "name": "Faculty of Engineering", "description": "Main administrative building for engineering students.", "latitude": 6.01234, "longitude": 10.25678, "type": "building" } ] }

AI Guidance: Display results in a dropdown or a list with icons based on type (e.g., "building", "landmark", "external").

INTELLIGENT ROUTING (POST /navigation/navigate)
The core of the app. Calculates routes and generates human-like descriptions.

Request: { "query": "Take me to the Library", "user_location": { "source": "gps", "lat": 6.010317, "lon": 10.258816 }, "travel_mode": "walking" }

Response (Status: success): { "status": "success", "message": "Start by walking North towards the Fountain. After 50m, turn left reaching the Library main entrance.", "destination": { "id": "lib_01", "name": "Main Library", "latitude": 6.015, "longitude": 10.26 }, "route": { "coordinates": [[6.010, 10.258], [6.012, 10.259], [6.015, 10.26]], "distance": 450.5, "duration": 300 } }

AI Guidance: If status is "success", render the route.coordinates on a map (e.g., Leaflet or Mapbox). Display message as a toast or a detailed instruction card.

NAVIGATION CHATBOT (POST /navigation/chat)
A conversational assistant for general questions.

Request: { "message": "Is the cafeteria open today?", "session_id": "user_session_123456", "user_location": { "source": "gps", "lat": 6.01, "lon": 10.25 } }

Response: { "status": "success", "message": "The Main Cafeteria is open until 6 PM. It is located just 200m from your current position!", "session_id": "user_session_123456", "metadata": { "action_taken": "search", "results_found": 1 } }

AI Guidance: Implement a chat bubble UI. Always send the same session_id to maintain conversation history.

================================================================================ FINAL YEAR TOPICS SERVICE
TOPIC CRUD & STATISTICS
Method	Endpoint	Description
GET	/topics/	Get all topics. Use department and option query params for filtering.
POST	/topics/	Create a new topic. Required: title, department, option, year.
GET	/topics/stats/overview	Returns counts for the Dashboard charts.
Example Topic Object: { "topic_id": "topic_99", "title": "AI-Driven Smart Campus Guide", "department": "Computer Engineering", "option": "Software Engineering", "year": 2025, "status": "reserved", "keywords": ["AI", "Navigation", "FastAPI"] }

AI TOPIC TOOLS
A. Suggest Topics (POST /topics/ai/suggest) Generates 3-5 unique project ideas based on a department.

Request: { "department": "Computer Engineering", "option": "Power Systems", "count": 3, "user_request": "I want something involving solar energy." }

Response: { "suggestions": [ { "title": "Solar Tracking using IoT", "description": "A system that rotates panels to maximize sunlight exposure.", "keywords": ["IoT", "Solar", "Arduino"] } ] }

B. Improve Topic (POST /topics/ai/improve) Refines a draft title and description.

Request: { "title": "Old bad title", "description": "Short description", "department": "Mechanical Engineering", "option": "Manufacturing", "user_instruction": "Make it sound more professional." }

Response: { "improved_title": "Design and Optimization of automated manufacturing units...", "improved_description": "A comprehensive analysis of...", "suggested_keywords": ["Automation", "CAD", "Optimization"], "suggested_status": "available" }

================================================================================ OFFLINE & CACHE MANAGEMENT
The frontend should periodically check /api/cache/status and download updated data via /api/cache/data.

Cache Data Structure: { "locations": [ { "id": "1", "name": "Gate", "coordinates": [6.0, 10.2], "is_on_campus": true } ], "metadata": { "generated_at": "2025-12-18", "total_locations": 150, "version": "1.0" } }

================================================================================ COMMON ERROR CODES & HANDLING
Code	Meaning	AI Action
400	Bad Request (Field missing/duplicate)	Show validation error on form.
404	Not Found	Show "Location not found" empty state.
429	Rate Limit Exceeded	Show "Slow down!" message and disable buttons for 10s.
500	AI/Server Timeout	Show "AI is taking a nap" message with a retry button.
================================================================================ SESSION & MEMORY
To maintain a conversation history with the chatbots, always include a unique session_id (e.g., a UUID or UserID) in your chat requests. This allows the backend to retrieve previous messages from MongoDB and provide context-aware responses.

================================================================================ PRO TIP FOR THE AI FRONTEND AGENT
Use a vertical stepper for navigation instructions and a card-based grid for displaying topic suggestions. Always use the Swagger docs at /docs for interactive testing.
